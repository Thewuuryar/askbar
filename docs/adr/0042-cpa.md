# 0042. The `cpa` component

Status: Proposed
Date: 2026-11-08
Kind: component
Source: plan step 1.14 ([plan-v1.md](../plan-v1.md)); owner rule that every component has an ADR of its own (2026-11-07)

## Context

`cpa` is CLIProxyAPI, a third-party program that turns a ChatGPT or Claude subscription login into an OpenAI-compatible provider. It was in the stack before the rule that each component has its own ADR. Its image and supervisor already have one ([0037](0037-askbar-cpa-image-and-supervisor.md)); this record covers the component as a whole, as it is on `main` after plan step 1.11. It follows [0005](0005-no-controller-and-self-restart.md), [0014](0014-model-gateway-and-providers.md), [0017](0017-dependencies-and-patches.md), [0028](0028-service-boundaries-and-config-delivery.md) and [0032](0032-container-hardening.md).

## Decision

- **What it is:** the pinned CLIProxyAPI image under the `askbar-cpa-supervisor`, image `askbar-cpa` ([0037](0037-askbar-cpa-image-and-supervisor.md)), plus `deploy/cpa/README.md`. It starts with the stack and idles until an account is connected on the admin site's Services tab.
- **Configuration:** CLIProxyAPI reads its config only at start (tested in plan step 1.4). The admin writes `config.yaml` (the API key and control secret) to `cpa-config` before `cpa` starts. The supervisor restarts CLIProxyAPI when that file changes or when the admin writes a new value to `restart-request`, and confirms with `restart-done` ([0037](0037-askbar-cpa-image-and-supervisor.md)).
- **What it holds:** its config, written by the admin, in `cpa-config`; the subscription logins in `cpa-auth`, an exception to [0028](0028-service-boundaries-and-config-delivery.md) that [0014](0014-model-gateway-and-providers.md) records.
- **Volumes:** `cpa-config` (shared with the admin) and `cpa-auth`, mounted at `/root/.cli-proxy-api`.
- **Networks:** `edge` (the server calls its OpenAI-compatible API on port 8317, and it reaches the providers) and `cpa-admin` (the admin calls its management API). It publishes no port.
- **Links:** the server calls it with `cpa`'s API key, as an ordinary provider. The admin calls its management API with the control secret, to run logins and list accounts. It calls the subscription providers. It writes no audit record ([0003](0003-v1-service-layout.md)).
- **Hardening:** the shared defaults of [0032](0032-container-hardening.md), with one exception: it runs as `0:10001`. Root because CLIProxyAPI writes `/root/.cli-proxy-api`; group 10001, the admin's, like Caddy, so the supervisor can write the admin's mode-0660 `restart-done` with every capability dropped. It mounts nothing else that group could open. Memory limit 512 MB.

## Alternatives considered

Not recorded for the component; the supervisor's alternatives are in [0037](0037-askbar-cpa-image-and-supervisor.md).

## Consequences

`check-isolation.sh` tests that `cpa` runs the supervisor as its main process, publishes nothing, is on exactly these networks, and that a restart from the admin site restarts CLIProxyAPI without restarting the container. Updating CLIProxyAPI means changing the pinned digest and testing it ([0017](0017-dependencies-and-patches.md)).

**Where the code and an accepted ADR disagree:**

- [0014](0014-model-gateway-and-providers.md): `cpa` is connected to the server, as a provider the admin manages, not to `model-gateway`, which is not built yet (plan step 3.5).
- [0013](0013-backups.md): the subscription logins in `cpa-auth` are not in any backup yet, and `cpa` has no export route (phase 6).
