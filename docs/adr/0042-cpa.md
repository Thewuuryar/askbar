# 0042. The `cpa` component

Status: Accepted
Date: 2026-11-08
Kind: component
Source: plan step 1.14 ([plan-v1.md](https://github.com/Thewuuryar/askbar/blob/504481bc62e9290bb20be6401dfcf379a3bdedb6/docs/plan-v1.md)); owner rule that every component has an ADR of its own (2026-11-07)

## Context

`cpa` is CLIProxyAPI, a third-party program that turns a ChatGPT or Claude subscription login into an OpenAI-compatible provider. It was in the stack before the rule that each component has its own ADR. Its image and supervisor already have one ([0037](0037-askbar-cpa-image-and-supervisor.md)); this record covers the component as a whole, as it is on `main` after plan step 1.11. It follows [0005](0005-no-controller-and-self-restart.md), [0014](0014-model-gateway-and-providers.md), [0017](0017-dependencies-and-patches.md), [0028](0028-service-boundaries-and-config-delivery.md) and [0032](0032-container-hardening.md).

## Decision

- **What it is:** the pinned CLIProxyAPI image under the `askbar-cpa-supervisor`, image `askbar-cpa` ([0037](0037-askbar-cpa-image-and-supervisor.md)). It starts with the stack and idles until an account is connected on the admin site's Services tab.
- **Configuration:** CLIProxyAPI reads its config only at start (tested in plan step 1.4). The admin writes `config.yaml` (the API key and control secret) to `cpa-config` before `cpa` starts. The supervisor restarts CLIProxyAPI when that file changes or when the admin writes a new value to `restart-request`, and confirms with `restart-done` ([0037](0037-askbar-cpa-image-and-supervisor.md)).
- **What it holds:** its config, written by the admin, in `cpa-config`; the subscription logins in `cpa-auth`, an exception to [0028](0028-service-boundaries-and-config-delivery.md) that [0014](0014-model-gateway-and-providers.md) records.
- **Volumes:** `cpa-config` (shared with the admin) and `cpa-auth`, mounted at `/root/.cli-proxy-api`.
- **Networks:** `cpa-gateway` (`model-gateway` calls its OpenAI-compatible API on port 8317), `cpa-admin` (the admin calls its management API) and `outbound` (its route out to the subscription providers, shared with `model-gateway`, whose listeners are bound to the addresses of their own networks). It is not on `edge`, so it shares no network with Caddy. It publishes no port.
- **Links:** `model-gateway` calls it with `cpa`'s API key, as an ordinary provider. The admin calls its management API with the control secret, to run logins and list accounts. It calls the subscription providers. It writes no audit record ([0003](0003-v1-service-layout.md)).
- **From plan step 6.2, export and import:** the admin asks for them with request files on `cpa-config`, which the supervisor handles ([0037](0037-askbar-cpa-image-and-supervisor.md)): the export holds the account login files and is encrypted to the backup public key. No port is added ([0013](0013-backups.md)).
- **Hardening:** the shared defaults of [0032](0032-container-hardening.md), with one exception: it runs as `0:10001`. Root because CLIProxyAPI writes `/root/.cli-proxy-api`; group 10001, the admin's, like Caddy, so the supervisor can write the admin's mode-0660 `restart-done` with every capability dropped. It mounts nothing else that group could open. Memory limit 512 MB.

## Alternatives considered

Not recorded for the component; the supervisor's alternatives are in [0037](0037-askbar-cpa-image-and-supervisor.md).

## Consequences

`check-isolation.sh` tests that `cpa` runs the supervisor as its main process, publishes nothing, is on exactly these networks, and that a restart from the admin site restarts CLIProxyAPI without restarting the container. Updating CLIProxyAPI means changing the pinned digest and testing it ([0017](0017-dependencies-and-patches.md)).

**Where the code and an accepted ADR disagree:**

- [0013](0013-backups.md): the subscription logins in `cpa-auth` are not in any backup yet, and `cpa` has no export route (phase 6).

## Amendments

- 2026-11-12: connected to `model-gateway` (plan step 3.5, [0014](0014-model-gateway-and-providers.md), [0054](0054-model-gateway.md), owner's choice of 2026-11-12). Built so: `cpa` leaves `edge` and joins `outbound` for its route out, next to `cpa-gateway` and `cpa-admin`, so it shares no network with Caddy; the isolation script checks its networks and who is on `outbound`. The admin's managed provider is made once CPA lists a model, so after the first account is connected, not at first start (before that there is no model to name); the gateway reaches it at `cpa:8317` with the key the admin keeps. A pasted login address has to be the address the login's own URL sends the browser back to (scheme, host, port and path, taken from its `redirect_uri`), carry the login's state, come within 10 minutes and be used once; it and its one-time code are on no record the admin keeps. The control API's paths and shapes were checked against the pinned image (v8.0.51) with `scripts/check-cpa-image.sh` (login URLs for both providers and where each sends the browser back, the refusals for a wrong state, an unknown state and no secret, and the account list); finishing a real login needs an account and a person, and was not tried.
- 2026-11-11: design for plan step 6.2 (#70, D26): export and import through the supervisor's request files. The code PR adds the 'built' line.
- 2026-11-12: built the export (plan step 6.2, PR AK; [0013](0013-backups.md), [0037](0037-askbar-cpa-image-and-supervisor.md)): the backup bundle's `cpa.age` holds the account login files from `cpa-auth`, encrypted by the supervisor to the backup public key; the admin only passes the bytes on and empties the copy on `cpa-config`. No port added. The import is PR AM.
