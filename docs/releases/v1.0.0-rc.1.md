# Askbar 1.0.0-rc.1

Askbar is a Spotlight-style AI popup. You press a hotkey, a bar appears, you type a question, read the answer and press Esc. Your own server holds the conversations and the provider keys, and the desktop app is a thin client that pairs with it. It is an open-source project for personal hardware (AGPL-3.0-or-later), with no support or uptime guarantee.

This release candidate is the scope of [ADR 0002](../adr/0002-v1-scope-limits-and-ship-criteria.md): conversation only (text in, text out: no tools, no shell, no file access), on a server split into separated containers.

## What is in it

New in this release since 0.6.0 (the full list is in the changelog below):

- **Separated services.** The auditor, the model gateway and the alerter run as their own containers, each with its own networks and volumes. The server has no outbound route and no provider keys ([architecture](../architecture.md)).
- **A tamper-evident audit trail.** Every record is chained to the one before by hash, a provider call waits until its audit record is acknowledged, and the admin site warns when the chain does not match. Prompts and replies stay sealed by a passphrase only the owner knows.
- **Encrypted backups and restore.** Scheduled or by hand, to a backup key the admin creates, with a Restore page for an empty install.
- **Alerts** by ntfy or email, for rejected tokens, audit problems, restart loops, low disk, budgets and new releases.
- **Budgets, a kill switch and a per-user pause**, enforced by the model gateway; the admin site approves the models users can pick, and a chat can use its own model.
- **Admin site:** a privacy notice and an AI warning shown in the app, delete a user, pause a user, and the HTTP-01 certificate challenge beside DNS.
- **Stronger sign-in and browser safety.** A fresh sign-in for sensitive changes, a sealed-content session for audit content, Trusted Types in the popup and the admin site, and a link's whole address shown before it opens.
- **Release images** signed with keyless cosign, with an SBOM and provenance for each.

Carried over from earlier versions: a desktop popup for macOS, Windows and Linux opened with a global hotkey, any model provider (Anthropic, anything OpenAI-compatible, or a Claude or ChatGPT subscription through CLIProxyAPI), replies that run on the server, history and search, users and pairing keys, and HTTPS from the first start.

## Known limits

- **Size.** There is no fixed limit on users. The tested size is three active users, three simultaneous replies against the mock model, and about 200 ms of added latency at the 95th percentile before the first token (the provider excluded).
- **No guarantees.** No support and no uptime guarantee. A restart from the admin takes under a minute; the target for a restore on a clean host is under 30 minutes.
- **Not in 1.0.** Shared spaces for a family, memory and an iOS app (deferrable, [ADR 0002](../adr/0002-v1-scope-limits-and-ship-criteria.md)); projects, VPN access, arm64 images and renaming conversations ([the guide](../guide.md#not-built-yet)).
- **The desktop client** has no offline mode, and it cannot register a global hotkey on Wayland (bind a shortcut to the command `askbar` instead). The installers are not signed by Apple or Microsoft, so macOS and Windows show a first-open warning ([Verifying images and files](../guide.md#verifying-images-and-files)).
- **Alerts.** Nothing outside the host notices if the alerter itself is down ([ADR 0016](../adr/0016-risk-register.md)); the admin site shows a banner.

## The files of this release

- `compose.release.yaml`: the compose file with every image pinned by digest.
- The desktop installers for Linux, macOS and Windows, named `Askbar_<version>_<os>_<architecture>.<extension>` (for example `Askbar_1.0.0-rc.1_windows_x64.exe`).
- `askbar-1.0.0-rc.1-sboms.tar.gz`: an SBOM (SPDX) for each of the eight images.
- `SHA256SUMS` and `SHA256SUMS.sigstore.json`: the checksum of every file above, and its cosign signature.

The commands to verify the images and the files, and the identity to expect, are in [Verifying images and files](../guide.md#verifying-images-and-files).
