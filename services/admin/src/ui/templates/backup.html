Download an encrypted backup: one .tar file with the server's data (settings, paired clients and every space's conversations) and this admin's own (its database, its secret keys and the install's certificate). Each part is encrypted so that only your backup passphrase opens it: this admin cannot read it, and it holds everything one restore needs, secrets included.

The file holds manifest.json (which release made it and what is in it), backup-key.age (the private key, protected by your passphrase) and the encrypted parts. With the file and the passphrase, the age tool opens it; the guide says how. The auditor's store is in it too (audit.age, last). Without a backup passphrase set, nothing can be backed up.

To put a backup back, see Restore a backup below: it is for a new, empty install.

    Restore a backup

    A restore is for the start of a new install: it replaces the server's data and this admin's own with the backup's, and it is refused once anything has been set up here (a provider, a person, an API key or the audit passphrase). It needs a sign-in within the last 10 minutes.

    Choose the .tar file you downloaded from the Backup page. It is checked first (which release made it, and that no part is damaged) and a backup from a newer release is refused before the passphrase is asked for. Then enter the backup passphrase, the one that was set when the backup key was made: it opens the backup here and is never stored.
